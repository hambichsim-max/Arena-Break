### 1-4. 과제 — 대시 또는 조준 (대시)

후속 작업 커밋 6f513c5에서 왼쪽 Shift 대시를 별도 컴포넌트로 구현했습니다. 기존 플레이어 및 표적 배치가 담긴 미커밋 Arena 씬을 함께 저장했습니다. 이동 컨트롤러는 대시 변위를 받아 한 번의 Move로 적용합니다. 플레이 검증은 사용자 확인 예정입니다.


#### 시도 1

~~~text
Q 버튼을 눌렀을때 대쉬를 하게 해줘 
현 아키텍쳐 구조 참고하고 스크립트 또한 지금까지  만든 스크립트들 참고해서 만들어줘
~~~

**결과:**

`9ec2aa2`에서 PlayerController에 Q키 대시를 추가했습니다. 이동 입력 방향으로 대시하며, 이동 입력이 없으면 플레이어 전방으로 이동합니다. 기본값은 거리 5m, 지속 시간 0.2초, 쿨다운 1초이고 인스펙터에서 조절할 수 있습니다. 대시 이동은 CharacterController로 처리하며 수직 이동을 함께 적용합니다.

**문제점:**

과제 안내는 Shift 입력, 바라보는 방향으로 이동, 별도 컴포넌트 구현을 요구합니다. 현재 구현은 Q 입력과 이동 입력 방향을 사용하고 기존 PlayerController를 수정했습니다. 플레이 모드 동작과 두 번째 시도는 현재 기록에서 확인할 수 없습니다.

**원인 분석:**

프롬프트에서 Q키를 지정했고, 대시 방향과 별도 컴포넌트 조건은 명시하지 않았습니다. 구현은 기존 PlayerController의 이동 로직을 재사용했고, Q 입력용 액션을 코드에서 생성했습니다.

#### 시도 2 (수정 프롬프트 초안)

~~~text
1-4 과제 조건에 맞춰 대시 구현을 수정해줘. 왼쪽 Shift를 누르면 플레이어가 바라보는 수평 방향으로 짧게 돌진하고, 이동 키를 누르고 있어도 대시 방향은 유지해줘. 거리와 지속 시간, 쿨다운은 인스펙터에서 조절할 수 있게 해줘.

대시 기능은 별도 컴포넌트로 작성해줘. 이미 PlayerController에 들어간 Q키 대시는 대시를 추가하기 직전 버전의 상태로 되돌리고, 기존 이동과 점프 코드는 유지해줘. WeaponSystem은 수정하지 마. 끝나면 컴포넌트 연결 방법과 Shift 입력, 대시 방향, 쿨다운을 확인하는 방법을 알려줘.
~~~

**무엇을 바꿨나:**

Q 대신 왼쪽 Shift를 지정하고, 이동 입력 방향 대신 플레이어가 바라보는 수평 방향으로 대시하도록 요청했습니다. 별도 컴포넌트로 분리하고 기존 이동과 점프 동작을 유지하라는 조건을 추가했습니다.

**결과:**

실행 전 초안입니다. 코드 변경과 플레이 모드 결과는 아직 없습니다.

**배운 점:**

첫 프롬프트에서 입력 키, 대시 방향, 기존 코드의 수정 범위를 함께 지정하면 구현 결과를 과제 조건과 바로 대조할 수 있습니다.

### 2-1. 체력/데미지 설계 논의

#### 실제 요청

~~~text
2장까지 이어서 진행해줘 한단계씩 커밋 후 프롬포트.md 파일 작성해주고 검증은 내가할게
~~~

**설계 기록 (Codex 선택)**

- 공격자는 `IDamageable.TakeDamage(int)`만 호출합니다. 대상별 분기 없이 체력을 처리합니다.
- `Health`가 체력 변경과 사망 이벤트를 알리고, 적 컴포넌트가 사라지는 시점을 결정합니다. 같은 체력 컴포넌트를 표적과 플레이어에도 쓸 수 있습니다.
- HUD는 체력 변경 이벤트를 구독합니다. 무적 시간은 2장 범위에서 생략합니다.
